# 17. Server-Sent Events — 이해도 확인 문제

1. SSE는 어떤 방향의 통신에 적합합니까?
2. SSE는 왜 HTTP 기반이라고 합니까?
3. `text/event-stream`은 무엇입니까?
4. EventSource의 자동 재연결은 어떤 장점이 있습니까?
5. `Last-Event-ID`는 어떤 문제를 해결하는 데 사용할 수 있습니까?
6. SSE가 exactly-once delivery를 자동 보장하지 않는 이유는 무엇입니까?
7. SSE와 WebSocket의 핵심 선택 기준은 무엇입니까?
8. Proxy buffering이 SSE에서 문제가 되는 이유는 무엇입니까?
9. HTTP/2가 SSE connection 운영에 어떤 이점을 줄 수 있습니까?
10. AI 응답 streaming에서 SSE가 적합한 이유를 설명하세요.
11. SSE도 장기 연결이므로 운영상 고려해야 할 항목을 최소 5개 말해 보세요.
12. 60초 안에 SSE와 WebSocket을 비교해 보세요.

## 평가 기준

- Server → Client 단방향 stream을 이해하는가
- HTTP 기반이라는 의미를 설명할 수 있는가
- 자동 재연결과 delivery guarantee를 혼동하지 않는가
- Proxy/timeout/connection 비용을 말할 수 있는가
- WebSocket과의 선택 기준이 명확한가
