# 19. REST vs RPC — 이해도 확인 문제

1. REST와 RPC의 가장 핵심적인 추상화 차이는 무엇입니까?
2. Resource-oriented와 Action-oriented를 예시로 설명하세요.
3. REST가 HTTP method/status code semantics를 활용하는 장점은 무엇입니까?
4. REST = JSON, RPC = Binary라는 설명이 왜 틀렸습니까?
5. RPC가 복잡한 business command를 표현하기 쉬운 이유는 무엇입니까?
6. REST라고 자동으로 loose coupling이 되는 것은 아닌 이유를 설명하세요.
7. Idempotency가 Retry 설계에서 왜 중요합니까?
8. Public API에서 REST가 자주 선택되는 이유를 최소 4개 말하세요.
9. Internal service-to-service 통신에서 gRPC가 자주 선택되는 이유를 최소 4개 말하세요.
10. 외부 REST + 내부 gRPC 구조가 자연스러운 이유는 무엇입니까?
11. REST와 RPC 중 하나가 항상 더 빠르다고 말할 수 없는 이유는 무엇입니까?
12. 60초 안에 REST와 RPC의 선택 기준을 설명해 보세요.

## 평가 기준

- wire format이 아니라 API 추상화 차이를 설명하는가
- HTTP semantics와 idempotency를 연결하는가
- public/internal API의 현실적인 선택 기준을 말할 수 있는가
- REST/RPC를 절대적인 우열로 설명하지 않는가
