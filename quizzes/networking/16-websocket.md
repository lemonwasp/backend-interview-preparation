# 16. WebSocket — 이해도 확인 문제

자료를 보지 않고 자신의 말로 답합니다.

1. WebSocket은 어떤 문제를 해결하려고 만들어졌습니까?
2. Full-duplex란 무엇입니까?
3. WebSocket 연결은 일반적으로 어떻게 시작됩니까?
4. Polling과 비교했을 때 WebSocket의 장점은 무엇입니까?
5. 장기 연결이 많아질 때 서버가 관리해야 할 자원은 무엇입니까?
6. Ping/Pong 또는 heartbeat가 필요한 이유는 무엇입니까?
7. 여러 WebSocket 서버로 scale-out할 때 단순 Load Balancer만으로 충분하지 않은 이유는 무엇입니까?
8. Sticky Session의 장점과 단점은 무엇입니까?
9. WebSocket과 SSE의 가장 중요한 차이는 무엇입니까?
10. WebSocket이 TCP를 대체한다는 설명이 왜 틀렸습니까?
11. 10만 WebSocket 연결을 운영할 때 확인해야 할 항목을 최소 5개 말해 보세요.
12. Redis Pub/Sub이나 Kafka가 WebSocket 시스템에 왜 필요할 수 있습니까?
13. 60초 안에 WebSocket의 장점과 운영 비용을 함께 설명해 보세요.

## 평가 기준

- HTTP Upgrade와 장기 연결 구조를 설명할 수 있는가
- Full-duplex와 Server Push를 구분할 수 있는가
- FD/socket buffer/heartbeat 같은 운영 비용을 말할 수 있는가
- Scale-out 시 cross-node message delivery 문제를 이해하는가
- WebSocket과 SSE의 선택 기준을 설명할 수 있는가
