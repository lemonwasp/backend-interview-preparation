# 18. gRPC — 이해도 확인 문제

1. gRPC는 어떤 문제를 해결하는 framework입니까?
2. Protocol Buffers의 역할은 무엇입니까?
3. gRPC와 Protobuf가 같은 개념이 아닌 이유는 무엇입니까?
4. gRPC가 HTTP/2를 사용하는 장점은 무엇입니까?
5. Unary / Server Streaming / Client Streaming / Bidirectional Streaming을 각각 설명해 보세요.
6. gRPC가 REST보다 무조건 빠르다고 말하면 왜 부정확합니까?
7. Deadline과 Cancellation이 분산 시스템에서 중요한 이유는 무엇입니까?
8. `UNAVAILABLE`과 `INVALID_ARGUMENT`을 Retry 관점에서 다르게 봐야 하는 이유는 무엇입니까?
9. Protobuf field number를 함부로 재사용하면 왜 위험합니까?
10. Browser-facing public API에서 REST가 더 편할 수 있는 이유는 무엇입니까?
11. Microservice 내부에서 gRPC가 잘 맞는 이유를 최소 4개 말해 보세요.
12. gRPC를 사용해도 Partial Failure를 피할 수 없는 이유를 설명하세요.
13. 60초 안에 gRPC와 REST의 선택 기준을 설명해 보세요.

## 평가 기준

- RPC framework와 serialization format을 구분하는가
- HTTP/2와 streaming의 장점을 설명할 수 있는가
- deadline/retry/versioning까지 운영 관점으로 연결하는가
- gRPC를 단순히 "빠른 REST"로 설명하지 않는가
