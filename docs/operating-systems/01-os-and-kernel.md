# 01. 운영체제와 커널

## 이번 학습 목표

이 문서를 학습한 뒤 다음을 자신의 말로 설명할 수 있어야 합니다.

- 운영체제가 왜 필요한가?
- 운영체제는 어떤 자원을 관리하는가?
- 운영체제와 커널은 무엇이 다른가?
- 애플리케이션은 왜 하드웨어를 직접 제어하지 않는가?
- 파일 저장과 메모리 사용은 운영체제와 어떻게 연결되는가?

---

## 1. 컴퓨터를 하나의 식당이라고 생각해보자

컴퓨터를 큰 식당이라고 가정합니다.

- CPU는 실제로 요리하는 요리사입니다.
- 메모리는 조리대입니다.
- 디스크는 식재료 창고입니다.
- 네트워크 장치는 배달 출입구입니다.
- 프로그램은 동시에 들어오는 주문입니다.
- 운영체제는 주문과 자원을 관리하는 총괄 관리자입니다.

주문이 하나뿐이라면 관리가 단순합니다. 하지만 브라우저, 메신저, 서버,
데이터베이스처럼 여러 프로그램이 동시에 실행되면 문제가 생깁니다.

모든 프로그램이 마음대로 CPU를 사용하려 하고, 같은 메모리 위치를 덮어쓰고,
동시에 디스크와 네트워크 장치를 조작한다면 시스템은 곧 망가집니다.

운영체제는 다음과 같이 중재합니다.

```text
여러 애플리케이션의 요청
          ↓
       운영체제
          ↓
CPU / 메모리 / 디스크 / 네트워크 장치
```

한 문장으로 정리하면:

> 운영체제는 여러 프로그램이 하드웨어 자원을 안전하고 효율적으로 나누어
> 사용할 수 있도록 관리하고, 복잡한 하드웨어를 사용하기 쉬운 형태로 제공하는
> 시스템 소프트웨어다.

---

## 2. 운영체제가 없다면 어떤 문제가 생길까?

### CPU 충돌

CPU는 한 코어에서 한 순간에 하나의 명령 흐름만 실행할 수 있습니다.
여러 프로그램이 동시에 실행되려면 누가 언제 CPU를 사용할지 정해야 합니다.

운영체제는 실행할 작업을 선택하고, 일정 시간이 지나면 다른 작업에 CPU를
넘겨줍니다. 이것이 CPU Scheduling의 출발점입니다.

### 메모리 충돌

프로그램 A가 사용하는 메모리를 프로그램 B가 마음대로 수정할 수 있다면
데이터 손상뿐 아니라 비밀번호 같은 정보도 노출될 수 있습니다.

운영체제는 각 Process에 독립된 주소 공간이 있는 것처럼 보이게 만들고,
허용되지 않은 메모리 접근을 차단합니다.

### 장치 제어의 복잡성

SSD, 키보드, 네트워크 카드의 제조사와 동작 방식은 서로 다릅니다.
모든 애플리케이션이 장치별 제어법을 직접 구현한다면 프로그램 개발이 매우
어려워집니다.

운영체제는 Device Driver와 공통 인터페이스를 제공해 이러한 차이를 감춥니다.

## 3. 운영체제의 핵심 역할

| 역할 | 쉬운 설명 | 백엔드 연결 |
|---|---|---|
| CPU 관리 | 실행할 작업의 순서와 시간을 정한다 | 요청 처리 Thread와 Context Switching |
| 메모리 관리 | 프로그램에 메모리를 배분하고 서로 격리한다 | Heap, OOM, Page Fault, GC 아래의 OS 메모리 |
| 프로세스 관리 | 프로그램의 실행과 종료를 관리한다 | 서버 Process, Worker Process |
| 파일 관리 | 데이터를 파일과 디렉터리 형태로 제공한다 | Log, Upload, 임시 파일, DB 파일 |
| 장치·I/O 관리 | 복잡한 하드웨어 접근을 대신 처리한다 | Disk I/O, Network I/O |
| 보호와 권한 | 허용된 작업만 수행하게 한다 | 사용자 권한, Process 격리, Port 접근 |

운영체제는 단순히 Windows 화면이나 Linux 명령어를 뜻하지 않습니다.
GUI가 없어도 운영체제는 CPU·메모리·프로세스·장치를 계속 관리합니다.

## 4. 커널이란 무엇인가?

커널은 운영체제에서 가장 중심이 되는 부분입니다.

식당 비유로 보면 운영체제 전체에는 관리자, 업무 규칙, 안내 창구 등이 포함되고,
커널은 실제 자원실의 열쇠를 가지고 CPU·메모리·장치를 통제하는 핵심 관리자입니다.

커널은 높은 권한으로 실행되며 주로 다음을 담당합니다.

- CPU Scheduling
- Process와 Thread 관리
- 가상 메모리 관리
- 파일 시스템
- Device Driver
- 네트워크 처리
- 권한과 보호

### 운영체제와 커널의 차이

```text
운영체제
├── Kernel
├── System Library
├── Background Service
├── Shell
└── 사용자 도구
```

엄밀히 말하면 커널은 운영체제의 핵심 구성 요소이고, 운영체제는 커널을 포함한
더 넓은 시스템 환경입니다. 다만 일상적인 설명에서는 두 용어가 느슨하게
섞여 사용되기도 합니다.

면접에서는 다음처럼 답하면 안전합니다.

> 커널은 운영체제의 핵심으로 CPU, 메모리, 프로세스와 장치를 높은 권한에서
> 관리합니다. 운영체제는 커널뿐 아니라 시스템 라이브러리와 서비스,
> 사용자 도구까지 포함하는 더 넓은 개념입니다.

## 5. 프로그램은 왜 하드웨어를 직접 제어하지 않을까?

애플리케이션이 디스크나 메모리를 마음대로 조작하면 다음 문제가 발생합니다.

- 잘못된 코드 하나가 전체 시스템을 망가뜨릴 수 있다.
- 다른 프로그램의 데이터에 접근할 수 있다.
- 여러 프로그램의 요청이 충돌할 수 있다.
- 하드웨어가 바뀔 때마다 애플리케이션도 다시 작성해야 한다.

따라서 애플리케이션은 운영체제에 작업을 요청합니다.

```text
애플리케이션: "이 파일을 저장해 주세요."
              ↓
운영체제: 권한과 요청을 확인
              ↓
파일 시스템과 Driver를 통해 장치 처리
              ↓
결과를 애플리케이션에 반환
```

애플리케이션이 운영체제 커널에 기능을 요청하는 공식 통로가 System Call입니다.
System Call과 사용자 모드·커널 모드는 다음 문서에서 자세히 다룹니다.

## 6. TIFF-to-PDF 성능개선 사례와 연결

기존 처리 방식에서는 TIFF의 각 페이지마다 다음 과정이 반복되었습니다.

```text
PNG 생성
  → 임시 파일 저장
  → 파일 재조회
  → PDF에 추가
  → 파일 삭제
```

이 과정은 단순한 메서드 호출처럼 보이지만 실제로는 파일 시스템을 통한
생성·쓰기·읽기·삭제 작업과 데이터 복사를 반복합니다. 운영체제의 파일 캐시가
일부 접근을 빠르게 만들 수는 있지만, 파일 API 호출과 메타데이터 처리,
사용자 공간과 라이브러리 사이의 복사 비용까지 사라지는 것은 아닙니다.

이를 `MemoryStream` 기반 처리로 변경하면서 임시 파일 경로를 제거했고,
페이지마다 반복되던 파일 시스템 I/O 비용을 줄일 수 있었습니다.

이 사례는 다음 원칙을 보여줍니다.

> 애플리케이션 성능 문제처럼 보이는 현상도 CPU, 메모리, 파일 시스템,
> 시스템 콜 같은 운영체제 관점으로 내려가면 병목의 원인이 더 선명해진다.

## 7. 자주 하는 오해

### “운영체제는 화면과 메뉴다”

GUI는 운영체제가 제공하는 사용자 환경 중 하나일 뿐입니다. 서버용 Linux처럼
GUI가 없어도 운영체제의 핵심 기능은 정상적으로 동작합니다.

### “커널과 운영체제는 완전히 같은 말이다”

커널은 운영체제의 핵심이지만 운영체제 전체보다 좁은 개념입니다.

### “프로그램 여러 개가 CPU를 동시에 소유한다”

여러 코어에서는 실제 병렬 실행이 가능하지만, 각 CPU Core는 매우 짧은
시간 단위로 여러 작업을 교체하며 실행할 수도 있습니다. 이 빠른 전환 때문에
사용자는 여러 프로그램이 동시에 실행되는 것처럼 느낍니다.

### “임시 파일을 사용하면 반드시 매번 물리 디스크까지 접근한다”

운영체제의 Page Cache나 파일 캐시 때문에 항상 물리 장치까지 즉시 접근한다고
단정할 수는 없습니다. 그러나 파일 생성·읽기·삭제와 관련된 운영체제 및
파일 시스템 처리 비용은 여전히 발생합니다.

## 8. 60초 면접 답변

> 운영체제는 여러 프로그램이 CPU, 메모리, 디스크와 네트워크 장치를 안전하고
> 효율적으로 공유하도록 관리하는 시스템 소프트웨어입니다. 또한 파일,
> Process, 가상 메모리처럼 하드웨어를 사용하기 쉬운 추상화로 제공합니다.
> 커널은 운영체제의 핵심 부분으로 높은 권한에서 Scheduling, 메모리,
> Process와 장치를 직접 관리합니다. 애플리케이션은 하드웨어를 직접 조작하지
> 않고 System Call을 통해 커널의 기능을 요청합니다. 이를 통해 자원 충돌을
> 방지하고 보안과 이식성을 확보할 수 있습니다.

이 문장을 그대로 외우는 것이 아니라, 다음 확인 문제에 자신의 표현으로
답할 수 있어야 합니다.

## 핵심 요약

```text
운영체제 = 자원 관리자 + 하드웨어 추상화 + 보호 장치
커널     = 운영체제에서 높은 권한으로 핵심 자원을 관리하는 부분
```
